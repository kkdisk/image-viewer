# v2.5 改版計畫：非破壞式調整與雙圖比較

更新日期：2026-10-18。基準版本：v2.4.1。

狀態：M1–M3 已完成開發與自動化驗證；M4 發布審查進行中，候選版本為 `2.5.0`。正式標籤需等待本次 commit 的 CI 通過；詳見 [發布前審查](V2_5_REVIEW.md)。

## 1. 目標與範圍

讓使用者能安心嘗試調整、取消預覽、復原與重做，並在同一個視窗比較原圖、編輯結果或另一張照片。

v2.5 的「非破壞式」指本次開檔期間保留載入時的原圖，調整預覽不直接覆寫已套用的圖片。儲存仍輸出一般圖片；一般檔案沿用 Ctrl+S 儲存至目前路徑的行為，因此儲存可能覆寫來源。介面須明確區分「套用調整」與「儲存檔案」，另存新檔仍可用。跨程式重啟保留可編輯參數、圖層、RAW 處理及專案檔不在本版範圍。

| 優先級 | 功能 | 完成定義 |
| --- | --- | --- |
| P0 | 調整預覽、套用與取消 | 五個滑桿共用一次調整工作階段，取消可回到進入調整前的圖片 |
| P0 | Undo / Redo | 一次套用只產生一筆歷史；復原後可重做，新增編輯清除 redo 分支 |
| P0 | 背景結果與儲存一致性 | 過期結果不得更新新圖片、覆蓋取消操作或污染歷史 |
| P1 | 原圖／結果並排比較 | 左側為本次載入時原圖，右側為目前結果，兩側標示清楚 |
| P1 | 另一張圖片比較 | 可將本機圖片固定為左側參考，不改變右側編輯文件與 Filmstrip |
| P1 | 同步縮放與平移 | 可開關同步，支援符合視窗與 100% 顯示，尺寸不同時有一致規則 |

跨資料夾播放清單、影片續播、影片截圖與重複圖片保留建議列為後續候選，不併入 v2.5。

## 2. 目前程式與改動位置

以下為本次規劃時的程式狀態，並非 v2.5 已完成項目：

- `ImageModel` 管理目前圖片、效果基準與 PNG 暫存復原紀錄，尚無 redo 或原圖獨立生命週期。
- `_apply_adjustments()` 已從固定基準合併白平衡與細緻調整；每次執行仍會經 `_apply_effect()` 建立復原點。
- `EffectController` 以效果編號區分工作；停止、換圖與取消後的結果有效性還需要文件與預覽版本檢查。
- 圖片頁目前為 `QScrollArea + QLabel`，影片是獨立頁面；比較頁應維持相同的媒體分流。
- 壓縮檔暫存圖片已要求另存至外部位置，v2.5 必須保留此保護。

## 3. 調整與歷史的操作規則

### 3.1 圖片狀態

區分三份邏輯狀態，實作可用磁碟快照減少常駐記憶體：

- **載入時原圖**：完成 EXIF 方向校正後的圖片；用於原圖比較，本次文件存續期間不變。儲存不會改寫這份比較基準，重新開檔才更新。
- **已套用圖片**：目前編輯文件的正式結果，是儲存與歷史紀錄的依據。
- **調整預覽**：從進入調整時的已套用圖片與目前五個參數計算；不直接取代已套用圖片。

### 3.2 操作行為

| 操作 | 預期行為 |
| --- | --- |
| 第一次修改滑桿 | 開始調整工作階段，保存固定基準與進入前狀態 |
| 繼續修改滑桿 | 合併五個參數重新預覽；不新增歷史，連續請求只保留最新待算參數 |
| 套用 | 等待最新參數的完整解析度結果成功，才提交一筆歷史並重設滑桿 |
| 取消 | 立刻使預覽工作失效，還原進入前顯示、滑桿與未儲存狀態，不新增歷史 |
| 重設調整 | 將五個滑桿回到中性值，保留工作階段；不等同取消 |
| Ctrl+Z / Ctrl+Shift+Z | 有調整工作階段時停用；其餘時間分別復原／重做已提交的編輯 |
| 旋轉、翻轉、濾鏡、縮放尺寸 | 有待處理調整時，先詢問套用／放棄調整／返回，再執行一般編輯 |
| Ctrl+S / 另存新檔 | 有待處理調整時先使用相同詢問流程；返回或運算失敗不得寫檔 |
| 開檔、Filmstrip、拖放、上一個／下一個、關閉 | 先處理待處理調整，再沿用文件的儲存／放棄／取消詢問 |
| 切換比較模式或更換參考圖 | 不提交編輯、不變更未儲存狀態，也不處理右側未完成調整 |

套用中、復原讀檔中或一般效果運算中，停用衝突的編輯與儲存操作。取消預覽可使結果失效，但不強制終止正在執行的原生函式。

沒有像素變更的套用不新增歷史。復原／重做恢復圖片與對應狀態；儲存成功記錄目前歷史位置，回到該狀態時解除未儲存標記，離開該狀態則恢復標記。

## 4. 雙圖比較的操作規則

- 新增「比較」入口，預設左側顯示載入時原圖，右側顯示目前預覽或已套用結果。
- 提供「選擇參考圖片」與「恢復原圖參考」。參考圖片為唯讀，開啟失敗時保留原參考與右側狀態。
- 兩側顯示來源名稱、尺寸與角色；左側不提供編輯或儲存操作，所有調整作用於右側。
- 參考圖片使用既有靜態圖片格式規則，支援 EXIF 方向校正、檔案大小檢查與背景載入；影片不作為比較參考。
- 使用可調整寬度的左右分割區，保持長寬比，透明圖片使用一致的棋盤背景。
- 預設同步縮放與平移。同步時採相同的每像素縮放倍率與正規化中心座標，各側依自己的邊界夾持；不做自動特徵對齊。
- 「符合視窗」讓兩張圖分別完整顯示，此時可有不同倍率；下一次手動縮放以操作側的倍率同步兩側。「100%」則兩側均為一個影像像素對應一個顯示邏輯單位，另驗證 Windows DPI 行為。
- 關閉同步後可各自操作；重新啟用時以右側視圖為基準同步。同步事件需阻擋回授，避免兩側互相觸發更新。
- 離開比較回到單圖模式時保留右側視圖與編輯狀態。比較模式下沿用媒體導覽：換到另一張圖時結束原調整流程、重建原圖基準；另選的參考圖保持固定。
- 換到影片時離開比較並釋放比較快取，影片沿用現有播放行為；再次開啟比較時預設使用當前圖片的原圖。

## 5. 實作架構

| 元件（新檔名為規劃） | 責任 |
| --- | --- |
| `core/image_model.py` | 文件狀態、原圖來源、已套用結果、文件版本與歷史位置 |
| `core/edit_history.py` | 歷史游標、唯一快照檔名、Undo / Redo、儲存位置與容量清理 |
| `core/adjustment_controller.py` | 固定基準、五項參數、預覽排程、套用／取消及待處理調整流程 |
| `core/effect_controller.py` | 背景運算、文件與請求版本驗證、過期結果回收、工作結束生命週期 |
| `core/comparison_controller.py` | 參考來源、唯讀載入、比較模式與視圖同步 |
| `ui/comparison_view.py` | `QSplitter` 與兩個 `QGraphicsView`，顯示與輸入事件 |
| `ui/ui_manager.py` | 套用／取消、Redo 與比較入口，集中更新可操作狀態 |
| `core/editor_window.py` | 整合上述元件與共用的媒體切換流程，避免新增另一套歷史或開檔邏輯 |

預覽請求在 UI 執行緒擷取純參數與圖片副本；背景工作不得讀取滑桿或其他 QWidget。每個結果附帶文件版本及預覽請求版本；取消、換圖、復原與關閉均使舊結果失效。失效結果只釋放資源，不更新直方圖、顯示、歷史或錯誤對話框。

歷史快照改用唯一檔名，先成功寫入再改動歷史游標；讀取失敗不得丟掉可用的復原點。快照保留上限沿用 `MAX_UNDO_STEPS`，undo 與 redo 共用此預算；新增預算或預覽設定時納入 `Config.validate()`。

原圖快照、歷史與比較圖共用明確的資源擁有權；快照不足、記憶體不足時顯示失敗並保留已套用結果。禁止為單一圖片同時保留多個無上限的完整解析度縮放快取。先使用完整解析度背景預覽，實測後才決定是否加入低解析度快速預覽。

儲存採同目錄暫存輸出，完成編碼後才取代目標；失敗時保留來源與未儲存標記。PNG 透明度與支援的 ICC／EXIF 資料需明確測試，EXIF 方向不得重複套用；JPEG 不支援透明度時採明確的背景色規則。比較預覽與縮圖不得用作最終輸出。

## 7. 驗證對應

預計新增 `tests/test_edit_history.py`、`tests/test_adjustment_controller.py`、`tests/test_comparison_controller.py` 與 `tests/test_comparison_view.py`，並擴充現有編輯／媒體切換測試。使用事件或受控 worker 重現競態，不依賴任意 sleep。

Qt 測試沿用 `QT_QPA_PLATFORM=offscreen`；以專案已具備測試依賴的 `env\Scripts\python.exe -m pytest` 執行。自動化測試不取代 Windows 高 DPI、主觀流暢度或打包成品的人工驗證。

實作與驗證紀錄見 [v2.5 開發版驗證報告](V2_5_VALIDATION.md)。Windows 高 DPI／雙螢幕人工操作、真實照片效能及遠端 CI 尚未完成驗證，不宣稱 v2.5 可正式發布。
